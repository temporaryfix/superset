## Self-contained schema prerequisite

[Schema PR #8232](https://github.com/superset-sh/superset/pull/8232) owns matching Drizzle source and generated migrations together: retained GitLab integration/automation enum values, cloud-project metadata, environment-project metadata and workspace-checkout metadata. Three generated indexes cover organization cleanup and connection cleanup in child tables. Existing tables, enum values and migration history remain intact; no existing-row rewrite or backfill is introduced.

The complete co-located database test belongs with this prerequisite. Its three static checks exercise parameterized typed upsert, selected-connection lookup and enum parsing. Its five gated real-DDL cases exercise exact text IDs, case, time zones, defaults, JSON state, scoped uniqueness, missing-parent refusal and deletion cascades. All eight cases passed against the canonical full-migration disposable database. A combined run with four tRPC fixture files passed 42 tests and 226 assertions with zero skips/failures; repeating it passed the same 42 tests and confirmed cleanup. It imports DB declarations and the direct PostgreSQL test driver, with no application/API/host/client dependency. The database package declares the driver as a development dependency. A second three-case static test adds no distinct coverage and is removed when the complete test is moved. The feature’s separate tRPC test driver remains scoped to that package.

The GitLab application proposal keeps the same schema definitions when composed. Landing the prerequisite first gives later generation and application typechecking one canonical schema. Rollback disables application behavior and retains the additive metadata; it does not automatically drop stored links or PostgreSQL enum values.

## Actual PostgreSQL evidence

An owned disposable PostgreSQL 18 database applied the full 146-migration chain, then repeated the migration invocation with the same recorded count. It verified six foreign keys and the three new covering indexes. The measured additive migration ran in 49.27 milliseconds while nine concurrent parent-read/child-write operations completed; the slowest measured operation was 18.71 milliseconds. The rehearsal used a five-second lock timeout and a one-minute statement timeout. Text project IDs, branch defaults, timestamps, connection uniqueness, parent refusal and connection/workspace/environment cascades passed the SQL contract checks.

A separate arm64 transfer rehearsal exported 1,000 fixture rows from PostgreSQL 17.11 and imported them into PostgreSQL 18.6. Ordered checksums matched, including Unicode JSON and integer identifiers above JavaScript’s safe-integer range. Restarting PostgreSQL 17 retained its original checksum. An additional PostgreSQL 18 write left the old database unchanged; the old owned resources were removed after verification. The rehearsal used disposable fixture data and bounded statement/lock settings.
